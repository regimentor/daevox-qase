# Иерархия сьютов на странице выполнения запуска

Status: done
Owner: Codex

## Problem

Источник: [GitHub issue #9](https://github.com/regimentor/daevox-qase/issues/9).

На странице выполнения запущенного test run слева отображается плоский список test cases с поиском и фильтром по статусу. Пользователю нужно проходить запуск по test suites: видеть сьют, его кейсы, следующие сьюты и отдельно кейсы, добавленные без сьюта.

## Scope

Включено:

- заменить плоский навигатор кейсов иерархичным деревом сьютов и их кейсов;
- отображать вложенные сьюты с сохранением иерархии;
- показывать кейсы без сьюта отдельно после дерева сьютов;
- сохранить поиск по кейсам, фильтр по статусу, выбор текущего кейса и отправку результата;
- согласовать последовательную навигацию с порядком кейсов в дереве.

Исключено:

- изменение состава запуска и редактирование repository со страницы выполнения;
- изменение результатов, правил назначения и жизненного цикла запуска;
- изменение уже сохранённых immutable snapshots.

## Acceptance criteria

- [x] На странице выполнения вместо плоского списка отображаются узлы сьютов с вложенными кейсами запуска.
- [x] Вложенные сьюты отображаются внутри родительских; кейсы не дублируются.
- [x] Кейсы без сьюта доступны в отдельной группе после сьютов, в том числе в запуске без единого сьюта.
- [x] Сьюты можно раскрывать и сворачивать; выбранный кейс выделен, его ветка видна при переходе по прямой ссылке.
- [x] Выбор кейса открывает его snapshot и сохраняет существующий маршрут с идентификатором run case.
- [x] Поиск по названию/идентификатору кейса и фильтр по статусу работают совместно; дерево сохраняет родительские ветки найденных кейсов и показывает понятное пустое состояние при отсутствии совпадений.
- [x] Кнопки «Назад», «Далее» и переход к следующему непроверенному кейсу после отправки результата используют единый порядок обхода дерева, включая кейсы без сьюта.
- [x] Статусы кейсов обновляются после отправки результата; текущий кейс не теряется, если перестаёт соответствовать фильтру.
- [x] Переименование, перемещение или архивирование объектов repository после создания запуска не меняет отображаемую snapshot-структуру запуска.
- [x] Навигация доступна с клавиатуры; сохранены отображение прогресса, черновики шагов, вложения и ограничения завершённого запуска.
- [x] Добавлено frontend-покрытие для нескольких сьютов, вложенности, кейсов без сьюта, поиска/фильтрации и последовательных переходов.
- [x] Выполнены проверки для затронутых пакетов из `AGENTS.md`, результаты записаны в Implementation notes.

## Constraints and context

- Основные точки реализации: `frontend/web/app/widgets/execution-workspace/ui/ExecutionWorkspace.tsx` и `frontend/web/app/pages/run-execution/ui/RunExecutionPage.tsx`.
- Текущий виджет фильтрует плоский массив `cases`, а переходы используют порядок исходного массива.
- В данных кейса уже есть `suiteMetadata`; при реализации проверить, достаточно ли snapshot-данных для восстановления иерархии и порядка, прежде чем расширять контракт.
- Дерево должно строиться по данным запуска, а не по текущему состоянию repository. Snapshot payloads остаются immutable, results — append-only.
- При необходимости изменения API прочитать контексты API/storage и явно описать контракт между пакетами; сохранить tenant isolation.
- GraphQL SDL — источник публичного контракта. После изменений схемы/операций запускать генераторы; generated artifacts вручную не редактировать.
- Соблюдать FSD layer order и публичные `index.ts` API.
- Исходный скриншот и описание ожидаемой структуры доступны в GitHub issue #9.

## Implementation notes

2026-10-06: задача перенесена из GitHub issue #9 в локальный формат (`ready`), затем реализована по TDD (`in-progress → done`). Пользователь подтвердил seams: публичный UI `ExecutionWorkspace` и `RunExecutionPage`, MSW только на границе GraphQL.

Дерево восстанавливается из существующего immutable `suiteMetadata`: вложенные сьюты объединяются по snapshot ID, порядок задаёт первое появление в snapshot case-position order, кейсы без сьюта идут последними. Поиск и статус обрезают готовое дерево без изменения порядка. Раскрытие доступно с клавиатуры; переход к кейсу раскрывает его ветку. Начальный выбор, «Назад», «Далее» и следующий непроверенный кейс используют полный порядок дерева независимо от фильтров.

API, storage, схема и snapshots не менялись. Обновлён `frontend/web/CONTEXT.md`. Добавлены 11 UI-интеграционных тестов на согласованных seams и Storybook-сценарий дерева. Новые поведения вводились отдельными циклами red → green; сохранённые возможности проверены регрессионными сценариями: прямой URL, отправка результата и обновление статуса/прогресса, текущий snapshot при фильтрации, черновики шагов, read-only завершённого запуска, кейсы без сьютов.
