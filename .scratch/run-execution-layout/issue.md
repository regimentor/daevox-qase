# Прокрутка, изменение ширины панелей и статистика сьютов в запуске

Status: ready
Owner: Codex

## Problem

Источник: [GitHub issue #14](https://github.com/regimentor/daevox-qase/issues/14).

На странице просмотра/прохождения запуска боковые панели должны прокручиваться независимо от страницы. Пользователю нужна возможность менять их ширину и видеть количество кейсов и статусы прохождения внутри свёрнутых сьютов.

## Scope

- Независимая вертикальная прокрутка списка кейсов и панели результата попытки.
- Начальная ширина левой панели вдвое больше текущих 260 px: 520 px на широком экране, с ограничением по доступному месту.
- Изменение ширины обеих боковых панелей на desktop с сохранением доступного места для контента.
- Прокрутка страницы определяется центральным контентом кейса.
- Сьюты по умолчанию свёрнуты; заголовки содержат количество кейсов и распределение текущих статусов.
- Адаптация для узких экранов, сохранение поиска, фильтров и последовательной навигации.

Изменение API, базы данных, состава запуска и правил отправки результатов не входит в задачу.

## Acceptance criteria

- [ ] Длинный список кейсов и длинная панель результата имеют собственную прокрутку и не увеличивают высоту страницы; обе панели остаются доступны при прокрутке центрального контента.
- [ ] Длинный центральный контент увеличивает прокрутку страницы.
- [ ] На достаточно широком экране начальная ширина левой панели равна 520 px.
- [ ] Обе боковые панели можно изменять по ширине мышью и с клавиатуры; ограничения ширины не допускают перекрытия или исчезновения центрального контента.
- [ ] На узких экранах панели остаются доступны без переполнения страницы по горизонтали; desktop-ресайз отключён.
- [ ] При открытии запуска все сьюты свёрнуты, включая ветку первоначально выбранного кейса; snapshot выбранного кейса отображается в центре.
- [ ] Явный переход к кейсу через «Назад», «Далее» или после отправки результата раскрывает его ветку; ручное раскрытие и сворачивание работает.
- [ ] У каждого сьюта показаны общее количество кейсов во всём поддереве без дублирования и количества UNTESTED, PASSED, FAILED, BLOCKED, SKIPPED; группа кейсов без сьюта имеет аналогичную статистику.
- [ ] Статистика рассчитывается по полному составу запуска, независимо от поиска и фильтра; после отправки результата актуализируется.
- [ ] Поиск и фильтр показывают подходящие кейсы с раскрытыми родительскими ветками; полный порядок последовательной навигации сохраняется.
- [ ] Сохранены прогресс запуска, черновики шагов, вложения и режим просмотра завершённого запуска.
- [ ] Поведение проверено компонентными тестами и в браузере: длинные панели/контент, вложенные сьюты, изменение ширины и узкий экран.
- [ ] Выполнены frontend-проверки из AGENTS.md, результаты записаны ниже.

## Constraints and context

- Читать `docs/architecture/CONTEXT-MAP.md` и `frontend/web/CONTEXT.md` перед реализацией.
- Основные точки: `frontend/web/app/widgets/execution-workspace/ui/ExecutionWorkspace.tsx`, `frontend/web/app/app/styles/global.css`, `frontend/web/app/features/result-submit/`.
- Сейчас desktop-сетка задаёт ширины 260 px / minmax(420 px, 1fr) / 360 px; механизма изменения ширины нет.
- Дерево уже построено по immutable snapshot `suiteMetadata`; текущие статусы доступны в `RunCaseFieldsFragment.currentStatus`.
- Текущее автоматическое раскрытие ветки выбранного кейса нужно согласовать с новым начальным свёрнутым состоянием. Описанное выше поведение — план реализации, а не текущее поведение системы.
- Сохранять snapshot-порядок дерева и навигации из задачи `.scratch/run-execution-suite-tree/issue.md`.
- Соблюдать FSD и публичные API слайсов. Generated artifacts вручную не редактировать.
