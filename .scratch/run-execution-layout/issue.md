# Прокрутка, изменение ширины панелей и статистика сьютов в запуске

Status: done
Owner: Codex

## Problem

Источник: [GitHub issue #14](https://github.com/regimentor/daevox-qase/issues/14).

На странице просмотра/прохождения запуска боковые панели должны прокручиваться независимо от страницы. Пользователю нужна возможность менять их ширину и видеть количество кейсов и статусы прохождения внутри свёрнутых сьютов.

## Scope

- Независимая вертикальная прокрутка списка кейсов и панели результата попытки.
- Начальная ширина левой панели вдвое больше исходных 260 px: 520 px на широком экране, с ограничением по доступному месту.
- Изменение ширины обеих боковых панелей на desktop с сохранением доступного места для контента.
- Прокрутка страницы определяется центральным контентом кейса.
- Сьюты по умолчанию свёрнуты; заголовки содержат количество кейсов и распределение текущих статусов.
- Адаптация для узких экранов, сохранение поиска, фильтров и последовательной навигации.

Изменение API, базы данных, состава запуска и правил отправки результатов не входит в задачу.

## Acceptance criteria

- [x] Длинный список кейсов и длинная панель результата имеют собственную прокрутку и не увеличивают высоту страницы; на desktop обе панели остаются доступны при прокрутке центрального контента.
- [x] Длинный центральный контент увеличивает прокрутку страницы.
- [x] На достаточно широком экране начальная ширина левой панели равна 520 px.
- [x] Обе боковые панели можно изменять по ширине мышью и с клавиатуры; ограничения ширины не допускают перекрытия или исчезновения центрального контента.
- [x] На узких экранах панели остаются доступны без переполнения страницы по горизонтали; desktop-ресайз отключён.
- [x] При открытии запуска все сьюты свёрнуты, включая ветку первоначально выбранного кейса; snapshot выбранного кейса отображается в центре.
- [x] Явный переход к кейсу через «Назад», «Далее» или после отправки результата раскрывает его ветку; ручное раскрытие и сворачивание работает.
- [x] У каждого сьюта показаны общее количество кейсов во всём поддереве без дублирования и количества UNTESTED, PASSED, FAILED, BLOCKED, SKIPPED; группа кейсов без сьюта имеет аналогичную статистику.
- [x] Статистика рассчитывается по полному составу запуска, независимо от поиска и фильтра; после отправки результата актуализируется.
- [x] Поиск и фильтр показывают подходящие кейсы с раскрытыми родительскими ветками; полный порядок последовательной навигации сохраняется.
- [x] Сохранены прогресс запуска, черновики шагов, вложения и режим просмотра завершённого запуска.
- [x] Поведение проверено компонентными тестами и в браузере: длинные панели/контент, вложенные сьюты, изменение ширины и узкий экран.
- [x] Выполнены frontend-проверки из AGENTS.md, результаты записаны ниже.

## Constraints and context

- Читать `docs/architecture/CONTEXT-MAP.md` и `frontend/web/CONTEXT.md` перед реализацией.
- Основные точки: `frontend/web/app/widgets/execution-workspace/ui/ExecutionWorkspace.tsx`, `frontend/web/app/app/styles/global.css`, `frontend/web/app/features/result-submit/`.
- До реализации desktop-сетка задавала ширины 260 px / minmax(420 px, 1fr) / 360 px без изменения ширины панелей.
- Дерево уже построено по immutable snapshot `suiteMetadata`; текущие статусы доступны в `RunCaseFieldsFragment.currentStatus`.
- Начальная ветка выбранного кейса остаётся свёрнутой; последующие переходы раскрывают его предков. Обновление результатов само по себе не раскрывает вручную свёрнутую ветку.
- Сохранять snapshot-порядок дерева и навигации из задачи `.scratch/run-execution-suite-tree/issue.md`.
- Соблюдать FSD и публичные API слайсов. Generated artifacts вручную не редактировать.

Обе панели ограничены по высоте и независимо прокручиваются; header и панели на desktop остаются видимыми при прокрутке snapshot. ResizeObserver учитывает фактическую высоту header и доступную ширину workspace. Ширины 520/360 px ограничены минимумами 260/280 px и резервом 420 px под snapshot; перетаскивание использует pointer capture, клавиатура — стрелки с шагом 20 px, Home и End. При ширине контейнера до 1023 px панели складываются вертикально, ресайз скрыт. Сохранение ширины между перезагрузками не добавлялось.

Статистика считается по полному snapshot-дереву, включает вложенные кейсы и обновляется с данными запуска независимо от фильтра. Сохранены последовательная навигация, черновики, read-only завершённого запуска и отправка результатов. API/storage/GraphQL-контракт не менялись, generated output после генерации не изменился.
