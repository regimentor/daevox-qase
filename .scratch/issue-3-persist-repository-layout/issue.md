# Сохранение размеров textarea метаданных suite

Status: done
Owner: Codex

## Problem

Пользователь может вручную увеличить textarea предусловий и постусловий выбранной Suite, но после перезагрузки страницы настроенная высота сбрасывается. Длинный текст также не должен оставаться скрытым в поле фиксированной высоты.

## Scope

Включено:

- сохранять пользовательскую высоту textarea предусловий и постусловий в браузере;
- восстанавливать высоту после перезагрузки страницы;
- хранить настройку отдельно для каждого проекта и каждого поля;
- автоматически увеличивать поле, если содержимому не хватает сохранённой высоты;
- ограничить изменение размера вертикальным направлением, чтобы не ломать сетку repository;
- добавить frontend-тесты поведения.

Исключено:

- серверное хранение UI-настроек;
- синхронизация размеров между браузерами или пользователями;
- изменение GraphQL-контракта или данных Suite.

## Acceptance criteria

- [x] Изменённая пользователем высота каждого поля восстанавливается после повторного монтирования/перезагрузки.
- [x] Предусловия и постусловия сохраняют размеры независимо.
- [x] Настройки размеров разных проектов не пересекаются.
- [x] Поле автоматически растёт под содержимое, если сохранённой высоты недостаточно.
- [x] Повреждённое или недоступное browser storage не ломает страницу.
- [x] Выполнены релевантные frontend-проверки.

## Constraints and context

- Изменение относится только к контексту `frontend/web`.
- Настройка размера не содержит доменных данных и остаётся локальной для браузера.
- FSD-границы и публичные `index.ts` API должны сохраняться.

## Implementation notes

- Источник: GitHub issue #3 — https://github.com/regimentor/daevox-qase/issues/3.
- Текущая реализация использует `Input.TextArea rows={3}` в `TestRepositoryPage` и не восстанавливает нативно изменённую высоту.
- Добавлен общий `PersistentTextArea`: он восстанавливает локальную высоту, отслеживает нативный resize, увеличивается под содержимое и деградирует без ошибок при недоступном `localStorage`.
- Ключи настроек включают `project.id` и имя поля, поэтому размеры проектов, предусловий и постусловий не пересекаются.
- В Storybook вручную проверен сценарий из issue: высота предусловий изменена с 74 до 165 px и сохранилась после полной перезагрузки iframe.
- Проверки пройдены: `npm run typecheck:web`, `npm run test:web` (15 файлов, 74 теста), `npm run build:web`, точечный `oxlint --deny-warnings backend frontend`, точечный `oxfmt --check` для всех изменённых файлов и `git diff --check`.
- Полный `npm run lint` проходит `oxlint`, но существующий `frontend/web/scripts/check-fsd-boundaries.mjs` на Windows строит путь `G:\\G:\\Projects\\...` и падает с `ENOENT`; изменение импортирует `shared/ui` из `pages` через публичный API и не нарушает FSD-порядок.
- Полный `npm run format:check` остаётся заблокирован существующим форматным drift в 354 файлах репозитория; все изменённые файлы проходят точечную проверку.
